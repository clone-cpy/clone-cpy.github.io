《代码整洁之道》重读笔记

2026年8月3日 ·1 分钟阅读 ·297 字

第一次读《代码整洁之道》是在刚工作那年，我把它当成一本「规范手册」，记下了命名长度、函数行数这些数字。几年后重读，才发现真正有用的部分和数字无关。

名字是设计的一部分

如果一段逻辑你没法用一句话命名，通常不是命名水平的问题，而是这段逻辑做了太多事。

// 说不清
function process(data) { ... }

// 一眼看懂
function normalizeUserProfile(raw) { ... }

注释解释「为什么」

好代码解释做了什么，注释解释为什么这样做。那些「循环遍历数组」的注释，删掉更好；而「这里必须延迟 200ms，否则 Safari 会丢焦点」的注释，价值连城。

函数应该只做一件事

这条被引用得最多，也最容易被误解。它不是要求函数短，而是要求函数只有一个改变的理由。

现在还会翻开它吗

会，但只翻前三章和第十七章。剩下的部分，不如去读真实的代码库。
